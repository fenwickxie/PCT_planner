# PCT-Planner 项目代码导读与调试手册

## 1. 项目解决什么问题

PCT-Planner 面向有楼层、坡道、桥下空间、顶棚等结构的地面机器人导航。单层高程图不能同时表达上下重叠的地面，完整三维体素图又会增加场景评估和搜索规模。本仓库的主流程是：

```mermaid
flowchart LR
    PCD[三维点云 PCD] --> T[Tomography：多高度切片投影]
    T --> C[GPU：地面/顶棚、可通行代价、膨胀、切片简化]
    C --> PKL[tomogram pickle]
    PKL --> L[TomogramPlanner：加载并初始化地图]
    L --> A[A*：多切片路径搜索]
    A --> G[GPMP：平滑和避障优化]
    G --> R[坐标恢复与 ROS nav_msgs/Path]
```

仓库主要分为两条链路：

| 目录 | 职责 | 主要入口 |
|---|---|---|
| [`tomography/`](../tomography) | 点云转 tomogram；依赖 CuPy/CUDA、Open3D 和 ROS | [`tomography.py`](../tomography/scripts/tomography.py) |
| [`planner/`](../planner) | tomogram 加载、A* 搜索、轨迹优化及 Python 绑定 | [`plan.py`](../planner/scripts/plan.py)、[`planner_wrapper.py`](../planner/scripts/planner_wrapper.py) |
| [`rsc/`](../rsc) | 示例点云压缩包、RViz 配置和可视化资源 | `rsc/pcd/`、`rsc/rviz/` |
| [`planner/lib/src/`](../planner/lib/src) | C++ 规划实现；pybind11 导出 Python 接口 | `a_star/`、`ele_planner/`、`map_manager/`、`trajectory_optimization/` |

## 2. Tomogram 生成：输入到持久化数据

### 2.1 场景配置与网格尺寸

运行 `tomography/scripts/tomography.py --scene <场景名>` 后，程序从 `tomography/config/` 按场景名取得配置，例如 `SceneSpiral`。场景文件指定 PCD 文件、网格分辨率、切片间距和可通行性参数。点云从 `rsc/pcd/` 读取，XY 轴边界取点云包围盒，中心取 XY 最小值和最大值的中点。网格尺寸按范围除以分辨率向上取整，并额外留出 4 个格子的边界余量。

垂直切片从 `ground_h + slice_dh` 开始，初始切片数由点云最高点和地面参考高度决定。`ground_h` 是构图参考值，不一定是机器人当前位置。变更 PCD 或场景配置后，应先确认点云坐标系、单位（米）、地面高度和切片范围一致。

### 2.2 点云投影与地图通道

[`Tomogram.point2map`](../tomography/scripts/tomogram.py) 调用 [`kernels.py`](../tomography/scripts/kernels.py) 中的 CuPy CUDA kernel。每个点按 XY 坐标落入二维格子；对每个切片平面：

- 平面以下的点更新该格子的地面高度候选值，保留其中最高的点；
- 平面以上的点更新顶棚高度候选值，保留其中最低的点；
- 没有点的格子用极端哨兵值表示无效，导出前转换为 NaN。

每层由此包含地面高度 `ground`、顶棚高度 `ceiling` 和间隙 `ceiling - ground`。CUDA kernel 以原子 min/max 处理多个点竞争同一格子的情况。

之后对地面高度计算邻域差分，并在 [`travKernel`](../tomography/scripts/kernels.py) 中评估：

1. **净空**：间隙低于 `interval_min` 时直接设为障碍代价；接近 `interval_free` 时增加惩罚。
2. **坡度/高度变化**：小变化按地面不平整度增加代价；超过站立阈值时检查跨步差异及邻域内可站立格子数量，不满足条件则设为障碍。
3. **安全膨胀**：在周围窗口上按距离权重传播较高代价，让路径离障碍留出安全距离。
4. **切片简化**：删除对可行区域没有新增贡献的中间切片，减少后续搜索状态。简化判断依据是相邻层的地面高度、代价及有效格子关系。

这些代价计算是代码层面的启发式规则，不能等同于对任意机器人动力学或碰撞外形的完整验证。

### 2.3 输出 pickle 数据格式

生成器将以下数组按通道顺序堆叠后写入 `<PCD文件名>.pickle`：

| `data` 通道索引 | 含义 | 形状 |
|---|---|---|
| `0` | 膨胀后的通行代价 `layers_t` | `[切片数, map_dim_x, map_dim_y]` |
| `1` | 代价沿网格 X 的差分 `trav_grad_x` | 同上 |
| `2` | 代价沿网格 Y 的差分 `trav_grad_y` | 同上 |
| `3` | 地面高度 `layers_g` | 同上 |
| `4` | 顶棚高度 `layers_c` | 同上 |

数组保存为 `float16`；字典元数据为 `resolution`、`center`、`slice_h0` 和 `slice_dh`。规划器加载后转换为 `float32`。`pickle` 不适合加载不可信来源的数据。更换切片/网格配置后应重新生成 tomogram，不能只修改 planner 参数而沿用旧地图。

`tomography.py` 会发布原始点云、逐层地面/顶棚和合并可视化点云。ROS 话题名和 `map` frame 见 [`tomography/config/param.py`](../tomography/config/param.py)。RViz 仅用于观察，不是 pickle 生成的必要数据来源。

## 3. 规划端数据流与接口

### 3.1 地图载入及切片连接

[`TomogramPlanner.loadTomogram`](../planner/scripts/planner_wrapper.py) 读取 pickle，将 5 个通道解包。无效地面高度替换为 `-100`，无效顶棚高度替换为 `1e6`，再将数组按每层二维网格展平成 C++ 接口需要的矩阵。

规划器由 [`OfflineElePlanner`](../planner/lib/src/ele_planner/offline_ele_planner.h) 统一持有 A*、稠密高程图和轨迹优化器。Python 入口 `init_map` 接收参数顺序为：

```text
cost_threshold, safe_cost_margin, resolution, num_layers, step_cost_weight,
cost_map, ground_height_map, ceiling_map, gateway_map, grad_x, grad_y
```

当前 wrapper 的调用值为 `20, 15, resolution, n_slice, 0.2`。注意 wrapper 将 `trav_gy` 传给 C++ 的 `grad_x`、`-trav_gx` 传给 `grad_y`，这是当前坐标轴/数组布局下的映射；改动数组轴顺序时要同步核对梯度方向。

切片间通道以 `gateway_map` 表示。wrapper 通过相邻层代价变化大于 8、地面高度差小于 0.1 米等条件推导上/下行 gateway，并写入正负标记。A* 在同一 XY 位置检查当前层及相邻层的 gateway 标记，决定下一步扩展在哪一层；因此 gateway 掩码错误时，常见表现是“同一平面可达、上下层无法连通”。

### 3.2 A* 搜索

[`Astar::Search`](../planner/lib/src/a_star/a_star_search.cc) 在每层二维网格上使用 8 邻域，按累计距离与通行代价组成的 `g` 值搜索，启发式默认是对角距离。高于 `cost_threshold` 的普通格子不可进入；gateway 相关分支允许检查相邻层的高度/可通行情况。`step_cost_weight` 控制代价权重，当前还存在低加权代价归零的截断逻辑（加权代价小于 5 时不加到路径长度上）。

在当前 wrapper 设置下，切片层数、代价图、高程图和 gateway 图必须严格同形。调试时可用 A* 的 `get_cost_layer()`、`get_ele_layer()` 和 `get_visited_set()` 查看代价、gateway 标记和展开范围。还需注意当前阈值为 20、权重为 0.2，而 A* 会把加权代价小于 5 的项清零：普通可进入格子的代价贡献因此通常为零，搜索主要按距离选择；调节权重时要同时考虑这段截断逻辑。

### 3.3 GPMP 轨迹优化

A* 路径转成 `PathPoint` 后，由 [`OfflineElePlanner::Plan`](../planner/lib/src/ele_planner/offline_ele_planner.cc) 调用选定的 GPMP 优化器。优化器以连续状态（位置及速度等）建模，加入起终点先验、GP 平滑先验和地图障碍因子，并在段间插值点检查障碍。地图查询由 [`DenseElevationMap`](../planner/lib/src/map_manager/dense_elevation_map.h) 提供，支持双线性代价查询及相邻层选择。

`ConfigPlanner.use_quintic=True` 时 wrapper 读取 `get_trajectory_optimizer_wnoj()`（六维状态版本）；设为 `False` 时读取 `get_trajectory_optimizer()`（四维状态版本）。当前 `plan.py` 设为 `True`。优化结果中位置与层索引再和地面/机器人参考高度组合，最后转换为地图坐标。

需要注意，`TomogramPlanner.plan()` 目前把起点、终点切片索引都固定为 0（源码中有 TODO），示例只从该层开始；它不是任意三维起终点接口。

### 3.4 坐标、数组与 ROS 输出约定

- PCD 和输出 `Path` 使用米制地图坐标 `(x, y, z)`，frame 为 `map`。
- tomogram 数组空间维度为 `(map_dim_x, map_dim_y)`；C++ 展平后矩阵行对应原数组 X 轴，列对应 Y 轴。
- `pos2idx()` 先减 `center`、除以分辨率并加地图中心偏移，然后交换 XY 索引顺序以适配 C++ 行列布局。`GetPathPoints()` 又按 C++ 的行列约定恢复路径点。
- [`transTrajGrid2Map`](../planner/scripts/utils/convertion.py) 负责从网格坐标恢复地图坐标；修改维度、转置或中心定义时，应同时检查输入点、RViz 地图和输出轨迹是否重合。
- [`traj2ros`](../planner/scripts/utils/vis_ros.py) 只发布位置，朝向设为单位四元数；优化器内部速度没有写入 `nav_msgs/Path`。

## 4. 运行方式与构建

README 列出的参考环境为 Ubuntu 20.04 及以上、ROS Noetic、Python 3.8 及以上、CUDA 11.7 及以上，以及匹配 CUDA 的 CuPy、Open3D。规划器 C++ 扩展还需要 Eigen、GTSAM 和 pybind11。

### 4.1 构建规划扩展

```bash
cd planner
./build_thirdparty.sh
./build.sh
```

先构建 GTSAM/OSQP，再构建 Python 扩展。`build_thirdparty.sh` 会删除其管辖的第三方 `build` 和 `install` 目录后重建；确认没有需要保留的构建产物再执行。`build.sh` 使用 `mkdir build`，已有同名构建目录时可能失败，应先按本地构建状态处理，不要误删源码或用户数据。运行 planner 前按 README 配置 GTSAM 的 `LD_LIBRARY_PATH`。

### 4.2 生成 tomogram

```bash
# 将示例 PCD 解压到 rsc/pcd/
roscore
cd tomography/scripts
python3 tomography.py --scene Spiral
```

可选场景：`Spiral`、`Building`、`Plaza`。程序需要 CUDA 可用的 CuPy、Open3D 与 ROS Python 环境。输出默认写入 `rsc/tomogram/`；建议检查终端输出中的切片数、地图尺寸和处理耗时，并在 RViz 核对地面层、顶棚层及通行代价。

### 4.3 运行规划示例

```bash
export LD_LIBRARY_PATH="$LD_LIBRARY_PATH:/绝对路径/PCT_planner/planner/lib/3rdparty/gtsam-4.1.1/install/lib"
cd planner/scripts
python3 plan.py --scene Spiral
```

示例的 tomogram 文件、起终点坐标在 [`plan.py`](../planner/scripts/plan.py) 中写死。修改场景时需确保文件名与 `rsc/tomogram/<文件名>.pickle` 对应；新增场景还要同时添加场景配置和示例的起终点。路径发布到 `/pct_path`。

## 5. 参数调试指南

修改场景构图参数的入口是 `tomography/config/scene_*.py`；规划参数在 [`planner/config/param.py`](../planner/config/param.py) 和 `planner/scripts/planner_wrapper.py`。源码中有些参数是直接写在 wrapper/C++ 中，不在配置类中。

| 参数 | 当前示例/入口 | 调大或调小的典型影响 | 调参建议 |
|---|---|---|---|
| `map.resolution` | Spiral 0.20 m；其他示例 0.10 m | 分辨率更细可保留狭窄结构，但网格和计算开销显著增加 | 以机器人足迹和点云密度为依据；更改后重建 tomogram |
| `map.slice_dh` | 0.5 m | 间距更大减少层数，但可能漏掉薄的可通行层；更小会增加层数和处理量 | 论文建议切片间距不大于机器人可通过的最小净空尺度；按场景中最窄的有效通道验证 |
| `ground_h` | 0.0 m | 改变首个投影平面的高度及覆盖区间 | 与点云地图高度基准保持一致 |
| `trav.interval_min` | 0.50 m | 提高会更保守地排除低净空区域 | 按机器人本体高度/可主动降低高度能力设定 |
| `trav.interval_free` | 0.65 m | 决定净空惩罚开始衰减的范围 | 与正常站立高度和期望的降身代价对应 |
| `trav.slope_max` | 约 0.36–0.40 | 改变可站立坡度阈值 | 和机器人最大坡度能力匹配；当前 kernel 将其转换为高度差阈值 |
| `trav.step_max` | 0.17–0.30 m | 控制跨步/单格高度差容忍度 | 结合地面分辨率和机器人越障能力调节 |
| `trav.kernel_size` | 7 格 | 增大窗口更强调整体可站立性，但可能排除局部窄区 | 通常保持奇数；先看地形梯度图，再改窗口 |
| `trav.standable_ratio` | 0.20–0.40 | 提高会要求邻域中更多平缓格子 | 过高容易把窄路判成障碍；过低可能保留危险孤立格 |
| `trav.safe_margin` / `inflation` | 0.4/0.2 m（Spiral safe margin 为 1.2 m） | 增大使障碍膨胀更宽、轨迹更保守，也可能封死窄通道 | 先对比膨胀前后 cost map 与机器人尺寸 |
| `cost_barrier` | 50 | 表示硬障碍代价 | 当前 A* 阈值为 20，需协调修改两处；不要只降低障碍值导致其变成可行格 |
| `max_heading_rate` | 10 | 优化器的转向变化约束参数 | 结合控制器限制测试；不可达或过度绕行时检查此值和轨迹因子 |
| `use_quintic` | `True` | 选择不同状态维度/GP先验的优化器分支 | 改值后确认 wrapper 取到匹配的优化器结果接口 |
| A* 参数 | wrapper 中 `20, 15, 0.2` | 分别影响 A* 代价门限、安全代价项和路径代价权重 | 搜索失败先看代价图与 gateway；避免盲目增大阈值 |

上述只是方向性调试提示。每次只改一组相关参数，固定同一地图和起终点，比较通行区域、路径长度、优化耗时及 RViz 结果；修改构图参数后必须重新生成 pickle。

## 6. 常见故障定位

| 现象 | 优先检查 |
|---|---|
| CuPy 报 CUDA/驱动错误 | CUDA 驱动、CUDA 运行时与 CuPy wheel 是否匹配；确认 Python 能创建 GPU array |
| 找不到 PCD | 解压位置是否为 `rsc/pcd/`；场景 `file_name` 大小写和扩展名是否正确 |
| tomogram 为空或只有 NaN | 点云轴向/单位、`ground_h`、`slice_dh`、边界范围，以及 GPU kernel 映射索引 |
| RViz 看不到话题 | `roscore` 是否运行、frame 是否一致、话题名是否与 RViz 配置一致 |
| planner 找不到 pickle | 检查 `planner/config/param.py` 的 `tomo_dir` 与生成目录；路径由 wrapper 拼接仓库根目录 |
| A* 报无路或 goal 不可达 | `get_cost_layer()` 中起终点代价、cost threshold、起终点索引、gateway 标记及相邻层高度 |
| 可以搜到路径但优化失败/结果异常 | 检查 A* 路径点数、`use_quintic` 选择分支、地图高度/顶棚有效值和优化器输出；当前 Python wrapper 在 `plan()` 失败后仍会继续读取优化器结果，排查时应先确认返回值 |
| 输出路径偏移、XY 对调 | 逐步打印 `center`、`pos2idx`、A* 返回行列索引和 `transTrajGrid2Map` 输出，检查是否重复交换轴 |
| 窄通道被封 | 检查安全膨胀范围、`kernel_size`、`standable_ratio` 和净空阈值；分别可视化膨胀前后代价 |

## 7. 代码接口速查

- Python 编排：[`TomogramPlanner`](../planner/scripts/planner_wrapper.py)：`loadTomogram(tomo_file)`、`plan(start_pos, end_pos)`。
- 规划总入口：[`OfflineElePlanner`](../planner/lib/src/ele_planner/offline_ele_planner.h)：`init_map(...)`、`plan(start, goal, optimize=True)`、`get_path_finder()`、`get_trajectory_optimizer*()`。
- A*：[`Astar`](../planner/lib/src/a_star/a_star_search.h)：`init(...)`、`search(start, goal)`、`get_result_matrix()`、`get_cost_layer(layer)`、`get_ele_layer(layer)`、`get_visited_set()`。
- 地图查询：[`DenseElevationMap`](../planner/lib/src/map_manager/dense_elevation_map.h)：双线性代价/梯度、层更新、地面高度和顶棚查询。
- ROS 轨迹：[`traj2ros`](../planner/scripts/utils/vis_ros.py)：将 XYZ 点转为 `nav_msgs/Path`。

Python 接口是 pybind11 从 C++ 导出的，类型签名参考 [`ele_planner.pyi`](../planner/lib/ele_planner.pyi)；扩展二进制必须与运行 Python/C++ 依赖兼容。

当前 `OfflineElePlanner::set_max_iterations()` 只更新四维状态优化器，而默认 `use_quintic=True` 读取六维状态优化器；若要调默认分支迭代次数，需核对对应 C++ setter，而不是只调用现有 wrapper 方法。

高度输出也有显式偏置：六维优化器默认 `reference_height` 为 0.1 m，`transTrajGrid2Map()` 又在 Z 转换中加 0.5 m。调试机器人轨迹高度或更换机器人时，应核对这一约定与目标机器人参考点定义，勿把它误认为纯地面高程。

示例 `plan.py` 的场景分支对未知名称会落到 Plaza 配置；运行自定义场景前应在脚本中显式添加分支，避免误加载 plaza tomogram。
